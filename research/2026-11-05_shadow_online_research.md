# Online research: shadow gradients — 2026-11-05

The user requested online research for techniques that could make SDR shadows richer and more varied. This is a research recommendation, not an implemented effect, validated candidate, performance claim or new approval to add passes. Existing profiles and the active shared shaders remain unchanged.

## Most promising research lead: local Laplacian contrast by scale

[Paris, Hasinoff and Kautz, Local Laplacian Filters (SIGGRAPH 2011)](https://people.csail.mit.edu/sparis/publi/2011/siggraph/) use intensity-dependent remapping and Laplacian-pyramid reconstruction to distinguish smaller local details from large image edges. The authors report detail manipulation and tone-mapping results without degrading edges in their examples; that is a paper result, not a guarantee for this shader or game footage. [Aubry et al., Fast Local Laplacian Filters (2014)](https://imagine.enpc.fr/~aubrym/projects/llf/index.html) develop an accelerated grayscale implementation and explicitly analyze gradient distributions. Their paper's relative speedup is not an actual game GPU performance estimate.

The potentially relevant idea is to treat shadow shade differences at distinct spatial scales, rather than making every pixel follow one scene-wide luminance curve. That is distinct from the rejected S-shaped shadow redistributions: those classified pixels primarily by brightness and could improve metal while compressing cool materials. It is also distinct from the adopted source-base method, which already carries pixel detail through Retinex/zone/lift but does not perform a complete local-Laplacian pyramid. An ordinary local-contrast/unsharp filter is not equivalent to a local Laplacian filter and should not be mislabeled as one. The CPU full-chain shadow model screened on November 5 used source-weighted windows, not a full local Laplacian implementation; its mixed results do not prove the latter cannot work.

**Proposed finite first step:** use current-profile, matched source and output images and independently calculate shadow-region contrast at multiple spatial scales, including the shelf, dark metal, cool window, bright sky/edges and a noise/quantization control. Establish whether the chain loses useful *mid-scale* shadow gradients that the adopted base does not retain. If there is no observable recurring loss, stop. If it exists, compare a faithful research reference implementation of local-Laplacian detail preservation, not a global shadow-brightness or strength sweep. Check source-fixed material relationships, native crops, black anchor, near-black smooth gradients, fine detail/noise, bright-dark edges and halo/temporal behavior. Only if a useful visible benefit and acceptable tradeoffs are demonstrated should a GPU approximation or extra effect/pass be considered; current GOAL treats sharpening/detail and noise-aware processing as exploratory, and no new effect is authorized simply by this research.

Risks: the 1/8- and 1/16-scale grade resources and 25-tap source base are not interchangeable with a true multiscale Laplacian pyramid; naively sampling them can make halos or lose detail. An implementation may need additional surfaces, passes, memory/bandwidth and temporal control. Existing `tools/noise_floor.py` can help characterize noise, but 8-bit game quantization, dither, grain, UI and motion are not a calibrated camera-noise model. Preserve the current profile, explicit SDR handling, existing history semantics and headless/private rules. Existing on-disk experiments do not establish that a fast GPU implementation is viable.

## Supporting leads, not selected implementations

[Eilertsen, Mantiuk and Unger, Real-time noise-aware tone mapping (SIGGRAPH Asia 2015)](https://computergraphics.on.liu.se/rntm/) combines edge-aware base/detail decomposition, local contrast-distortion-minimizing curves, noise visibility and temporal filtering. The relevant lesson is to test shadow changes against noise and temporal artifacts alongside contrast. Their HDR video and display-adaptive pipeline is not equivalent to this already-tonemapped SDR source; no camera-noise calibration, automatic exposure or display adaptation should be assumed here. Real-time in their context is not a performance guarantee for this shader.

[Shan, Jia and Brown, Globally Optimized Linear Windowed Tone-Mapping (2010)](https://grail.cs.washington.edu/projects/sq_tonemapping/) solves globally for overlapping locally linear windows. This suggests a useful research reference for preserving local tone order while respecting neighboring windows. The global optimization is not directly a small fixed-pass vkBasalt implementation, and its per-window monotonicity does not prove an arbitrary approximation is globally monotonic. The existing guarded tonal base already uses overlapping window estimates, but it is not this solver.

[Zhang et al., LUT meets Local Laplacian Filter (NeurIPS 2023)](https://proceedings.neurips.cc/paper_files/paper/2023/hash/b3a08d179347e33414badadf100e4e8d-Abstract-Conference.html) combines image-adaptive LUT tone manipulation with learned local-Laplacian detail processing for HDR tone mapping. It reinforces the separation of broad tone and local detail, but the learned model and HDR benchmarks do not justify adding neural inference or HDR output to this chain.

## Decision

Local-Laplacian and noise-aware work are established methods, not a claim of a newly invented algorithm. The research supports a multiscale *measurement and reference experiment*, not an immediate shader implementation. User-visible benefit, game content diversity, sRGB/SDR boundaries, near-black noise, halos and motion are the decision criteria. No current-stage strength retuning, mandatory sweep or rating change follows.
