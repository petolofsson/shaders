# Shared-component output-chroma proxy

The [output-chroma proxy](2026-11-06_output_chroma_proxy.md) made up-to-11-code changes to saturated foliage and a HUD element. This follow-up tests a **different safeguard**, scaling its zero-luminance correction by the common linear-RGB fraction `min(R,G,B)/Y`. It reduces those extreme screenshot changes while retaining some selected metal color separation. It also strengthens existing neutral-shadow casts, does little for the shelf's color by itself, and leaves the ordered brightness curve's cool-material losses. Native changes are subtle; **do not adopt or start a strength sweep on this evidence.**

The color component is `0.15 * shadow_gate * saturate(min(RGB)/max(Y,1e-8)) * (RGB-Y)`, with the prior common lower/upper SDR headroom factor. It is zero for exact neutral RGB because `RGB-Y=0`, zero for an SDR face with an exactly zero channel because the shared fraction is zero, and zero for zero grade-input gate. It has zero linear Y in ideal arithmetic. These identities are not a GPU or Oklab-hue contract. A weakly colored input need not be a neutral scene material, and a source-neutral pixel may already have an intentional shadow tint: this gate can enhance that tint. The correction is applied to independent 8-bit current-output and grade-input screenshots; the combined result additionally applies the [ordered brightness proxy](2026-11-06_ordered_shadow_design.md), then re-encodes. This is not a compiled candidate or exact same-update full-resolution image.
