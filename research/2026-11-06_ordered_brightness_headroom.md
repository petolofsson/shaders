# Ordered-brightness RGB headroom

The [ordered-brightness scalar construction](2026-11-06_ordered_shadow_design.md) is positive, but its proposed common RGB gain can push a valid saturated output above SDR range. The original offline screenshot proxy clips after applying that gain; scalar monotonicity does not establish color or clipping safety. A common-gain headroom limit prevents overrange for sampled nonnegative SDR colors, at the cost of reducing the requested brightening. This is a design contract screen, not a shader implementation or visual validation.

For output `rgb` and `y=Luma(rgb)`, the scalar model requests nonnegative luminance addition `c`. Straight scaling uses `rgb*(1+c/max(y,1e-12))`. With input gate fully engaged and `rgb=[0,0,1]`, the request gives `[0,0,1.01250584]`. A valid SDR input would therefore be clipped to the blue face if `saturate` followed directly. For nonnegative SDR RGB, bounding the common gain by `1/max(max(rgb),1e-12)` instead retains nonnegative channels and keeps each channel at or below one; exact zero remains zero. In double precision it preserves RGB ratios for nonzero channels, but it intentionally does not deliver the full requested luminance where headroom is exhausted. The limiting channel's identity and gain can change with color, so the earlier two-scalar monotonicity proof no longer proves ordering for the bounded RGB mapping. Near-zero, signed and positive-overrange inputs require separate policies.

An explicit counterexample confirms the limitation: with the gate fully engaged, neutral RGB `[0.0723,0.0723,0.0723]` has Y=0.0723 and receives bounded output Y≈0.0732022, while saturated blue RGB `[0,0.000279642,1]` has the higher input Y=0.0724 but remains at Y=0.0724 because its blue channel has no headroom. This is a synthetic cross-color comparison, not evidence that adjacent real materials reverse or that the two should have identical output brightness. It proves only that the cap does not provide a general luminance-ordering guarantee across different RGB colors.

The deterministic CPU test in `captures/ordered_brightness_headroom_20261106/` contains 400,000 SDR RGB samples, including 40,000 random single-channel face values and explicit saturated blue, with independently sampled source-gate luminance. Among 215,316 samples with positive correction, 421 produce at least one channel above one without the bound, maximum 1.01250584; the common gain cap engages in those 421. No sampled capped result is negative or above one by more than 1e-12. The maximum difference between requested and achieved Y is 0.0009029. These samples are deliberately synthetic, not actual shader states or a prevalence estimate. This check does not establish compiled-GPU precision, quantized-gradient continuity, temporal behavior, the original source-black handoff, or real-palette benefit.

On the two independently captured, decoded 8-bit current-output and diagnostic grade-input still pairs, the cap engages at zero pixels after masking the activity marker. This is an output-screenshot proxy without the new color operation, not same-update shader data or broad gamut coverage. Input and image digests and the exact check are in `stills.json` and `stills.py` in the same capture directory. It does not negate the synthetic face counterexample.

The cap and the [separate color headroom proposal](2026-11-06_output_color_headroom.md) are possible safeguards, not evidence that the current subtle visual candidates should be applied. The selected cool-material and neutral-color costs remain. No production shader, profile, configuration or rating changed.
