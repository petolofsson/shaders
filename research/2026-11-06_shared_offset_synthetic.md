# Shared-offset synthetic screen

**Decision: reject this particular local model before shader or image testing.** The black-anchored version leaves a simple smooth ramp almost unchanged, enhances a small step by creating opposing edge rims, and amplifies synthetic noise. These are pre-chain scalar CPU examples, not proof that every locally shared offset fails or that the artifacts would appear at these exact strengths in the full shader.

Starting from the [feasibility calculation](2026-11-06_shared_offset_feasibility.md), use a 5×5 bilateral linear-luminance neighborhood `m` with Gaussian spatial and half-stop log-range weights. Add `B * gate(x) * clamp(x/m - 1, -0.5, 0.5)` to the current scalar output `0.9925*x + 0.0025`. The gate smoothly fades in over input `x=0.0005–0.003` and out over `0.04–0.08`. These are exploratory fixed values, not tuned profile controls; `m` is computed from the scalar test input, not the actual post-inverse shader signal. The intent is to return to the original offset near black and share its effect over similar local luminances. No color, GPU, output encoding, or downstream processing is modeled.

The deterministic NumPy script and complete results are in `captures/shared_offset_probe_20261106/`. Inputs are continuous linear luminance except where specified. A constant black fixture and a 0-to-0.01 hard step exactly match the current scalar mapping; a constant 0.005 field matches to floating-point roundoff. A 256-pixel 0-to-0.02 linear ramp has no negative output steps, but changes at most 0.00000452 linear and its overall standard deviation barely changes. This narrow smooth-ramp result is not a general monotonicity proof.

A 0.005-to-0.006 step creates a roughly two-pixel dark rim on one side and bright rim on the other: the immediate edge corrections are -0.0001493 and +0.0001397 linear, fading to zero away from the edge. The resulting profile contains negative steps in both flat-side transitions. A 16-pixel-period sine centered on 0.005 gains about 5.0% standard deviation. In contrast, independent synthetic sRGB code-16 noise of ±1 code increases linear output standard deviation by 42.8%; ±3-code noise increases it by 35.0%. These deliberately adverse synthetic fixtures are not measured game noise, and their code-derived values are inputs to this isolated scalar model, not the real post-inverse input or encoded screenshots. The enhancement's sensitivity to high-frequency noise and generation of local edge reversals are nevertheless contrary to the requested unobtrusive shadow detail.

No actual-game appearance, color preservation, output quantization, neighborhood movement, performance, GPU contract or motion result is claimed. There is no justification for porting this version, a strength sweep, or changing production. A future coherent model would need evidence that it distinguishes meaningful fine shading from noise without edge rims; the earlier [noise-limited local-Laplacian](2026-11-05_local_laplacian_limited.md) and [graph screen](2026-11-06_shadow_graph_reference.md) already show the cost of simple suppression. The provisional color candidate and its unresolved reversal/neutral costs remain separate.
