# Local shared black-offset feasibility

The black-offset attribution suggests a concrete brightness mechanism: apply the configured offset as a gain shared within a material neighborhood, so that local brightness differences are not diluted by the same additive constant. A scalar fixed-neighborhood calculation shows why this is attractive, but also exposes a black-anchor failure at boundaries. This is an analytical screen, not an implemented or visually validated candidate. Production shaders and profiles remain unchanged.

For scalar linear luminance `x`, the present early mapping is `f(x)=a*x+B`, with `B=0.0025` and `a=WHITES-B=0.9925` in both current profiles. Its relative log slope at a fixed value `m` is `a*m/(a*m+B)`. A hypothetical locally shared mapping `g(x;m)=(a+B/m)*x`, for positive fixed neighborhood reference `m`, agrees exactly with the current mapping at `x=m` and has unit relative log slope within that fixed context. For `m=0.0025, 0.005, 0.01, 0.02`, current slopes are respectively 0.4981, 0.6650, 0.7988 and 0.8881; the hypothetical slope is 1. These slopes describe this one stage and do not predict the final image or prove a visible improvement. If `m` changes with `x`, its derivative also contributes, and downstream nonlinear processing changes the result.

The apparent benefit depends on applying a common gain to different pixels. It is not safe at a black boundary: with `m=0.01`, exact black maps to zero instead of the current stage's 0.0025; `x=0.001` maps to 0.0012425 instead of 0.0034925. Thus the construction cannot preserve the configured black anchor for black pixels adjacent to a brighter neighborhood. A pixel-dependent transition back to the additive offset may protect black, but changes the local slope and can create a boundary response. A neighborhood estimator can also straddle unrelated materials, move across edges or track noise; matching a flat-field value does not imply preserving local mean brightness. The adopted source tonal base is not automatically the correct post-inverse reference for this mapping.

This resembles the goal of the prior [offline black-offset detail transfer](2026-11-06_black_offset_detail_transfer.md), which obtained modest selected gains but increased several source-relative reversals. It is a different proposed mechanism, not a validated solution to those costs. The [black-anchored slope](2026-11-05_black_anchored_slope.md) and [late-offset](2026-11-05_late_black_offset.md) experiments are not evidence that this local model works. A viable continuation would first need an explicit, bounded black-preserving transition and an edge-aware reference, followed by an independent full-chain image screen against current and provisional color outputs. Flat fields, dark-to-light steps, near-black ramps, one-code noise and translation must challenge the model before any production consideration. No claim of GPU correctness, temporal stability, gamut safety, visible improvement or rating change follows from this scalar calculation.
