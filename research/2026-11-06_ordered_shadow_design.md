# Ordered brightness and grade-input color: offline design screen

This work continues the user's request for a functioning combined shadow treatment. A new scalar brightness construction fixes one specific flaw in the earlier source-gated curve: its continuous response is nondecreasing in *each* of its two scalar inputs. A separate output-stage color proxy refers to the existing grade input and preserves output luminance in ideal arithmetic. Together they improve some selected shelf metrics and reduce certain reversal costs compared with the earlier combined proxy, but the selected gains are subtle, cool-material response and neutral shifts remain, and neither mechanism has been tested in the shader. **Do not adopt on this evidence.**

## Brightness construction

Let `x` be post-inverse grade-input linear Y and `y` be the existing pre-dither output linear Y. Define `d=max(y-0.003864,0)`, `q=0.3*d/(1+d/0.004)`, `h=1-smoothstep(0.02,0.20,y)` and `g=smoothstep(0.0005,0.003,x)`. The proposed output Y is `y+g*q*h`. This is a different model from the earlier signed correction: its added term cannot be negative, so increasing only `x` cannot lower the output. With `g` fixed in [0,1], the `q` derivative is nonnegative; in the fading section `q<0.0012` and the maximum absolute slope of `h` is `1.5/0.18`, so the output derivative with respect to `y` is at least 0.99. Therefore if **both** input Y and existing output Y are ordered in the same direction, this continuous scalar mapping preserves that ordering. It makes no such promise when their orders disagree, after RGB/gamut/quantization, or for the preceding color operation. It cannot create the earlier negative gate derivative counterexample. The output is unchanged at zero grade-input Y, subject to the inverse handoff and actual shader arithmetic.

The pivot remains fitted to one shelf and no automatic context or appearance generalization is established. The positive correction necessarily brightens some values. A 4-rectangle screenshot calculation finds zero newly reversed continuous pairs among pairs whose diagnostic-input and existing output Y were strictly ordered in the same direction, at one- and four-pixel offsets. This is consistent with the analytical property but uses independent 8-bit images, not same-update GPU telemetry. See `captures/shadow_ordered_curve_20261106/pairs.json`; it does not erase the pre-existing color-candidate reversals.

## Alternative color proxy

The earlier color candidate corrects the early offset, and downstream processing can change its luminance and ordering. This screen instead takes the captured output RGB and the separately captured grade-input RGB. In linear RGB it scales the grade-input RGB to the current output luminance, then blends 15% toward that target with a zero-input gate and a fade over output Y 0.01–0.08. Both colors have the same Y before clipping, so their blend preserves Y in ideal arithmetic. This does not make it neutral-preserving: the grade input can already contain color, and blending toward it can undo intended color correction or print. An output RGB channel could require a headroom safeguard for other inputs; no clipped pre-color channels appeared in these two whole-frame proxies. It does not recover a lossless signal, and its 15% coefficient is an exploratory choice, not user tuning or an optimized value.

The color and brightness proxies use independent 8-bit screenshots, calculate in float, and quantize the final result. This is not a GPU implementation, pre-quantization readback, motion observation or proof that the source-black pixel reaches grade input zero. The screenshots and production/profile/config hashes are identified in `captures/shadow_output_color_20261106/report.json`; current production hashes match the earlier color capture's recorded identity. Both input/output capture histories retain their own static-repeat limitations.

## Decision and open work

The ordered scalar construction removes a specific mathematical failure of the previous gate without needing an estimated output-black texture. It does not solve the selective cool-material or palette issues. Before any shader candidate, a stronger held-scene visual case and a design that respects intended source and print color are needed. In particular, validate real warm/red-black and muted scenes, the quantized noise floor, exact black through inverse, source-relative ordering when input/output disagree, and controls for legitimate shadow color grading. Compiled GPU contracts and measured same-update motion/cuts remain entirely untested. The screenshots do not justify adopting this model or changing profiles, configs or ratings.
